== Rules
- R-I Every change MUST trace to a backlog id: by its `Refs:` trailer when
  enabled, otherwise by its tracker entry.
- R-II A commit MUST serve exactly one backlog id; its tracker entry MUST
  be updated in the same step.
- R-III Ids MUST NOT be renumbered, reused, or deleted.
- R-IV An item MUST NOT be marked done until tests pass, it is live-verified
  and QA-approved.
- R-V The PM MUST add a defect's cause as a rule here before its fix is
  committed.
- R-VI Runs MUST write only inside the repository and MUST NOT use the
  system temp directory; scratch files go in the unversioned `scratch/`.
- R-IX `.spec/Confidential.adoc` MUST NOT be staged or committed.
- R-XI Only one agent MAY write the working tree at a time; the next MUST NOT
  be dispatched until the current iteration finishes or stops. A concurrent
  writer silently discards uncommitted work.
- R-XIV The code author's tests MUST NOT count as independent evidence. A
  capability whose failure causes harm MUST NOT be marked done until
  something outside this repository has exercised it.
- R-XXI Rule, iteration and ADR ids MUST be roman numerals: `R-IV`, `IT-IV`,
  `ADR-IV`.
- R-XXII Every run MUST scan committed sources for upstream names, including
  its legacy format names, before committing; a constant copied from upstream
  MUST be renamed or dropped when it names such a format.
- R-XXIII A nullable lookup MUST NOT be the mapper of `Optional.map`: a null
  result silently becomes empty and falls through to the `orElse` branch.
- R-XXIV A decoding loop MUST make progress or fail on every iteration: a
  call that consumes and yields nothing (input exhausted, dictionary
  needed) MUST raise a corrupt-data error.
- R-XXV Every tool JVM the build starts (test forks, mutation minions,
  analysers) MUST have its temp directory set inside the repository by
  the build itself; the caller environment MUST NOT be relied upon.
- R-XXVI A build plugin that forks a JVM MUST let the build set that
  JVM's options; a fork with fixed options writes outside the repository
  (perf data under the fixed system temp path) and cannot be corrected.
- R-XXVII A temp-location rule MUST name only writes the repository can
  control; JVMs started by an external launcher before project settings
  apply (a launcher probe) are outside it.
- R-XXVIII A tool JVM forked by a build plugin with fixed options and no
  option hook (R-XXVI) is outside repository control; its perf data,
  unlinked at exit, is not a temp-location violation.
- R-XXIX Figures in a review file (tests, mutations, coverage) MUST be
  copied from the gate log summary lines of the final run, never computed
  or carried over; a wrong figure lowers the self-review score.
- R-XXX An encoding or decoding MUST NOT be marked done without at least
  one byte vector derived from the reference encoder (source or output);
  a round trip of the port against itself is not evidence.
- R-XXXI An order-preserving encoding MUST match the reference byte sequence
  and length; ordering and round trips alone do not establish compatibility.

Retired, never reused: R-VIII, R-XVI, R-XVIII, R-XIX.
Optional rules: <<optional-rules>>; Kick-Off selects those that apply.
