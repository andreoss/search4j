= CQ-IV QueryParser and Weight Quality Checkpoint
Status: done
Self-review: 6/10

== Goal

Bring the sources committed between IT-XX to IT-XXXII back under the
quality gate: Qulice zero violations with no exclusions, the full
regression suite green, and the public weight API shaped so that no
interface declaration exceeds the parameter limit.

== Findings

- The gate was red at `7930cc5`: `mvn verify` reported 1416 Qulice
  violations, concentrated in `EnquireImpl` (250), `QueryParserTokeniser`
  (88), the matcher operators and the weight schemes. Earlier iteration
  reviews reported a green gate; those reports do not reproduce.
- The gate is sensitive to the JDK. On JDK 25 the bundled ErrorProne
  2.50.0 crashes inside `StringConcatToTextBlock` and
  `UnnecessaryParentheses`, and checkstyle reports twice as many
  violations; on JDK 21, the toolchain the project targets, the same tree
  reports 765.
- `EnquireImpl` held 174 violations: static nested classes, comments,
  `++`, inline conditionals, nested conditionals and single-use locals.
  Its advanced options also carried logic defects: the percentage cutoff
  compared a density rather than a score, the time limit was never
  consulted, and the collapse key was ignored.
- `Weight` declared a five-argument and a six-argument `weight` method;
  Qulice caps method declarations at three parameters.
- `ExternalPostList`, `MaxPostList`, `SynonymPostList`, `ValueGePostList`
  and `ValueRangePostList` validated arguments through a nested
  `*Parts`/`SourceParts` record in a delegating constructor, which the
  constructor rules reject.

== Changes

- `Weight` now takes `TermStats` and `DocStats`; `ExpandWeight` takes
  `ExpandStats`. The unused position overload is gone.
- `Enquire` merged the four-argument `getMSet` away; `EnquireImpl` was
  split into `MatchState`, `MSetImpl`, `MSetItemImpl`, `ESetImpl`,
  `ESetItemImpl` and `ExpandRun`, and all options are applied: sorting by
  document id, slot or key, score cutoff, time limit, collapse group,
  match spy and ESet generation.
- The `*Parts` records were replaced by prepared top-level records
  (`ValueRange`, `SynonymSpec`, `Bm25Norm`); constructors only assign and
  static factories validate.
- Validation errors that were `NullPointerException` are
  `InvalidArgumentError`.
- Scheme classes renamed to satisfy the abbreviation rule: `DlhWeight`,
  `DphWeight`, `LmWeight`, `TfidfWeight`.
- `ValueRangePostList.atLeast` replaces `ge`; `SynonymPostList` takes a
  `SynonymSpec`.
- `Matcher` was split into leaf, value, branch, scale and operator
  helpers; `LeafTermWeight` is a top-level class.

== Verification

- `mvn -Djava.io.tmpdir=scratch/tmp verify` on JDK 21:
  `Tests run: 2324, Failures: 0, Errors: 0, Skipped: 0`; Qulice
  `559 .java files against 1020 rules (243 Checkstyle, 284 PMD, 493
  ErrorProne)` with zero violations; `BUILD SUCCESS` at 14:52.
- Commit `81bca08`.

== Deviations

- `mvn verify -Ppitest` was started and aborted after 37 PIT minion
  timeouts under concurrent load from a second build on the same machine;
  mutation coverage is unverified. Earlier reports of 90% coverage predate
  the weight and Enquire code and do not cover it.
- The weight schemes and `Enquire` still have no unit tests; only the
  matcher wrappers that were already covered are exercised.
- JDK selection is external. The build cannot pin the JVM it runs on, so a
  caller on JDK 25 sees a red gate that is a tooling failure, not a source
  defect. Pinning a toolchain is left to the Owner.

== Self-review notes

The score is 6/10: the gate is green and the API is reshaped, but the
mutation gate is unverified, the new weight and Enquire code is untested,
and several defects found in that code were corrected without a
regression test.
